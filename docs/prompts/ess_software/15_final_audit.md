# 15 - Independently audit and close the delivered software scope

Execute the [shared contract](execution_contract.md) and
[verification rules](verification.md). Prerequisites: 14 and a factual
disposition for every earlier stage. This stage includes fixing confirmed
in-scope defects, not merely writing a report.

## Agent review and ownership

Lead integrates fixes, updates coverage and owns Git/final verification.
Spawn independent read-only reviewers for these bounded scopes, serially if
needed:

1. Vendor/API correctness: raw interpretations, access/windows, auxiliary
   semantics, bit-3 meaning, all 27 method assignments and retained guards.
2. Execution/ownership: actual core/app/owner paths, deadlines, effects, stale
   replies, result capacity, stop priority and no replay.
3. Consumption/documentation: public API completeness, CLI/host parity,
   source/install/platform evidence, truthful ledger and maintained guides.

Give reviewers current diffs and evidence, not only this prompt. Request exact
file/symbol and a reproducer or source contradiction for every finding. The
author of a subtle change is not its only reviewer.

## Audit and corrections

Trace each N01,N02,N04,N05,N07,N08 requirement from source to producing API,
ordinary app/CLI route, tests, public documentation and operation inventory.
Confirm all nine requested read records and two setting records individually.
Check interrupt semantics under real owner pressure, not just a changed bit.
Check each of the 27 method rows, not just descriptor counts or one generic test.

Review software claims against actual evidence. Keep 33/34/35 regressions;
unresolved 18/negative methods, nonzero offsets, raw scale questions and the
separate N03/N09/pair/physical backlog remain accurately described. A chosen
rejection contract or documented blocker is not full feature implementation.

Record findings as severity, file/symbol, evidence/reproduction, fix, regression
and remaining limit. Fix confirmed in-scope issues at their owning boundary;
simplify unnecessary wrappers/shadow state introduced by this set. Rerun focused
checks after corrections and required integrated/final-commit CI. Do not weaken
checks or adjust independent golden vectors merely to agree with code.

Recompute the checked inventory rather than subtracting overlapping baseline
counts. Update maintained API/CLI/homing guides, backlog, roadmap, root prompt
navigation, CHANGELOG and progress only where actual behavior changed. Preserve
historical evidence and the release 1.0.0 scope as a dated artifact. Do not tag,
publish or silently upgrade FieldCore's dependency.

## Exit and handoff

State delivered software, checks with exact commit/artifacts, final reviewer
dispositions, remaining software/source blockers and separate physical limits.
If all intended software was delivered, mark stages SOFTWARE COMPLETE and the
set complete. Otherwise report PARTIAL with the exact unfinished methods/routes
and next evidence/action; a disposition table alone cannot close the goal.

Archive only actually completed instructions under repository convention,
updating links without breaking historical references. Keep active blocked work
discoverable. Commit/push owned changes, confirm synchronization and report
required final-commit CI honestly. No remote campaign is needed for a final
documentation-only correction once the underlying implementation checks remain
applicable under current policy.
